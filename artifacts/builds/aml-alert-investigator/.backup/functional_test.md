# Functional Test Report — AML Alert Triage Agent

**Stage:** Functional Test
**System under test:** AML Alert Triage Agent (C-4 generation, C-5/C-6 groundedness verification)
**Inputs to this stage:** Model Risk Management documentation (SR 11-7) produced by the prior stage; no separate functional specification document was delivered to this stage. Acceptance criteria (AC-1 through AC-14) below are reconstructed from the Intended Use, Data Lineage, and Performance Measurement sections of that document, since those are the only normative statements of required behavior available. Where the upstream document itself flags an item as undefined or incomplete, that status is carried forward here rather than resolved by assumption.
**Test data:** `GOLD-600` (regression/accuracy suite), sequestered `GOLD-150` (SAR-recall holdout), plus a synthetic fixture set of 40 hand-built edge cases (missing fields, >500-row histories, non-English memos, PII-contaminated inputs) built for this stage because no such fixtures were supplied upstream.
**Test harness:** Functional assertions run against `AlertTriageResponse` objects; this stage does not re-run the E-1 statistical evaluation (disposition accuracy, macro-F1, ASR) — those are out of scope for functional test and are referenced only to mark dependency status.

## RESULT

**Overall:** 10 of 14 acceptance criteria pass within the scope this stage can test; 1 is explicitly out of scope for functional test (AC-6, owned by E-1); 3 are coverage gaps, one of which is blocking.

**Pass:** AC-1, AC-2, AC-3 (partial/dependent), AC-4, AC-5, AC-9, AC-10, AC-11, AC-12 (design-time), AC-14 (partial).
**Not covered / gap:** AC-7 (no SAR-recall threshold exists to test against — **blocking**, consistent with the model risk document's own statement that the model must not be promoted to production until this threshold exists, is reviewed, and is met), AC-13 (decoding parameters not pinned, so functional pass does not imply production determinism), AC-8 (row-selection algorithm for the 500-row cap untested because undocumented — functional pass covers only the crash/no-crash case, not correctness of what's retained), AC-14 new-typology sub-case (no fixture available).
**Out of scope for this stage:** AC-6 (disposition accuracy), macro-F1, groundedness fabrication rate at full corpus, and ASR — all owned by the E-1 harness and not re-measured here.

**Verdict:** Functional behavior that can be exercised today is sound — schema conformance, disposition enumeration, insufficient-data routing, PII exclusion, and verbatim-text capping all pass at 100% on the available samples. However, this stage cannot certify the system as release-ready, because the highest-severity acceptance criterion in the specification set (AC-7, `ESCALATE_SAR_RECOMMEND` recall) has no threshold to test against, and two further criteria (AC-8, AC-13) are untestable until upstream documentation gaps (row-selection algorithm; run-identity triple) are closed. Recommend the system remain blocked from production promotion until AC-7's threshold is defined and met on both `GOLD-600` and `GOLD-150`, and until AC-8 and AC-13 have either passing tests or an explicit, signed-off risk acceptance.
