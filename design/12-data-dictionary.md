|---|---|

Column-level definitions for the core entities. Classification follows
AMLI-DFD-001 §1. "Source" names where the value originates: `SAM` (Actimize
detection), `KYC` (party master), `SYS` (generated by this system), `HUM`
(entered by a person).

## 3. `transaction`

| Column | Type | Null | Class | Source | Definition |
|---|---|---|---|---|---|
| `transaction_id` | uuid | N | C4 | SYS | Surrogate key, part of the composite PK with `booked_at` |

| `booked_at` | timestamptz | N | C2 | SAM | System booking time; the partition key |
| `amount` | numeric(18,2) | N | **C2** | SAM | Never floating point |

| `medium` | text | Y | C2 | SAM | Cash, wire, cheque, card, ACH |
| `country_code` | char(2) | Y | C2 | SAM | Counterparty country where known |
| `reference_text` | text | Y | **C2** | SAM | Payment reference / remittance free text, **preserved byte-identical** |
| `reference_text_untrusted` | boolean | N | C4 | SYS | Always true where `reference_text` is present. The flag that drives envelope application (ADR-006) |

> `reference_text` is the only field in the model written by a party outside the
> institution's control. It is simultaneously evidence and the attack surface.
> It is never sanitised, never truncated, and never rendered outside the
> untrusted-data envelope.

### Labelling columns — never rendered to a model

| Column | Type | Null | Definition |
|---|---|---|---|
| `outcome` | enum | Y | **What the institution did.** Factual. `closed_no_action`, `escalated_to_case`, `sar_filed`, `ctr_filed`, `still_open` |
| `adjudication` | enum | Y | **What a qualified reviewer concluded was correct.** Independent of outcome |
| `adjudicated_by` | uuid | Y | The reviewer. Mandatory when `adjudication` is set |
| `adjudicated_at` | timestamptz | Y | When adjudicated |
| `label` | enum | Y | **The value used for scoring.** Null until adjudicated |
| `label_basis` | enum | Y | `adjudicated_qa`, `adjudicated_dual`, `filing_inferred`, `synthetic` |
| `label_confidence` | numeric(3,2) | Y | 0.00–1.00 |

Two database constraints make the policy structural rather than procedural:

- `alert_label_complete` — a label cannot exist without a basis and a confidence.
- `alert_ctr_never_labels` — a CTR outcome may never produce an inferred
  positive suspicion label.

These five columns are excluded by name from the rendering projection (FR-033).

## 12. Field-level rendering policy

What the model is permitted to see, by table. This is the minimisation control
(NFR-046) and is reviewed by the DPO.

| Table | Rendered to model | Never rendered |
|---|---|---|
| `party` | `party_type`, `legal_name`, `date_of_birth`, `occupation`, `annual_income`, `income_currency`, `city`, `state_code`, `country_code` | Internal identifiers |
| `account` | `account_type`, `product_name`, `currency`, `status`, `registration_type`, `opened_date` | Internal identifiers |
| `transaction` | `external_reference`, `event_date`, `amount`, `currency`, `direction`, `medium`, `country_code`, `reference_text` *(enveloped)* | `booked_at`, internal identifiers |
| `alert` | `scenario_code`, `description`, `triggered_values`, `run_date` | **`outcome`, `adjudication`, `label`, `label_basis`, `label_confidence`, `priority`, `score`** |
| `detection_version` | `rule_id`, `thresholds`, `source_document`, `source_page` | — |
| Everything else | — | All |

> `legal_name` and `date_of_birth` are rendered because an investigator needs
> them to assess identity-based typologies. This is a DPO-approved necessity,
> not a default, and it is the reason the prompt itself is retained under
> evidence controls rather than in general logs (NFR-048).
